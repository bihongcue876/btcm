# 副思考链模块（Beside-Thinking Chain Module, abbr. BTCM）设计理念
- 副思考链模块，作为大型集成Agent的辅助验证器官，用于验证与长链思考，支持联网搜索与验证（权威网站），或纯粹逻辑验证。
- 作为思考的模块，可以作为创意生成器。要求可以反复自思考和自验证，直到“自己觉得疲乏”再结束并反馈。正常是要求格式化输出。
- 要求可以人工控制使用需求，但集成Agent时，要求由其选择将什么录入进去。
- 自主配置本体系统与Web UI，要求允许配置与使用。
- 同时可以作为验证模块的范式以供移用。

# 整合
- 副思考链模块，作为大型集成Agent的辅助思考器官，支持验证和创意生成，并有反思模块。
- 要求可以控制使用需求与使用量，有不同的内置Agent与思维格式。
- 自主配置本体系统与控制面板Web UI，要求允许配置与使用。
- 作为思维模块的范式，以供调用使用。

# 现状落定（alpha）

以下为原始设计意图在 alpha 实现中的具体落地形式，以 `share/protocol.md` 与 `docs/Agents.md` 为权威：

- **“反复自思考与自验证，直到疲乏”** → 转为机械终止规则：`validation_passed` / `controller_stop` / `max_iterations` / `timeout`，总控的 meta 级反思（`decision=stop`）可提前收敛，但 verifier 判 `fail` 时不得定稿、硬性上限永不可突破。行为完全可预期，不依赖模型自报置信度。
- **“联网搜索与验证（权威网站）”** → 经 MCP 联网工具落地。内置预设 tavily / exa / deepwiki / fetch（Streamable HTTP），经 OpenAI function calling 调用；“可用才调用”——服务器不可用静默退回纯逻辑验证，不报错。工具输出以资料包裹（非指令）并标注上限 12000 字符。
- **“控制使用需求与使用量”** → `enable_creative` / `enable_validator` 双开关组合四种运行形态（完整循环/纯创意/纯验证/长链持续思考），`/api/invoke` 并发上限 4（429 `RATE_LIMITED`），`data.usage` 返回 prompt/completion tokens 与调用次数（有效 token 计量）。
- **“自主配置本体系统与 Web UI”** → 后端 `btcmodule/btcm.json`（Pydantic 校验，`GET /api/config` 不回显密钥），`PUT /api/config` 原子写入。前端 Vue3 面板（三页：运行/配置/日志），`unplugin-vue-components` 按需分包，`pnpm build` 自动同步至 `btcmodule/static/` 单端口托管。
- **“作为思维模块范式以供移用”** → 三个 Agent 与循环结构独立于宿主，`Engine` 无状态、纯函数式入口；`core/llm.py` 按提供商注册表 + Agent 路由，任意 OpenAI 兼容模型即插即用；`core/mcp.py` 自研最小客户端，不引 SDK。
- **“格式化输出”** → 统一外层 `{success, data, error, request_id}`，`data` 按运行形态分化（verdict / candidates / conclusion + intermediate_log + usage）。
- **“管理员令牌”** → `admin_token` 仅写不回显，PUT /config、POST /config/reset、GET /logs 需 `X-Admin-Token` 头；invoke 与 GET /config 恒开放。
